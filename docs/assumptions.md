# Assumptions and their consequences

An assumption is a choice or condition on which a result depends. Some choices have source support; others make a bounded example possible. A passing check verifies only the condition it tests. The [glossary](glossary.md) explains terms, and [references](references.md) gives full citations.

| Assumption or decision | Reason and evidence | What is checked | What failure would mean |
| --- | --- | --- | --- |
| The declared selection defines the expected public-data grid. | One viral category per Saturday-ending week makes extract coverage explicit. This is an analysis choice, not a published count of eligible laboratories. | Ordered Saturday endpoints, supported categories, unique keys, scope, and missing slots are checked. | A wrong requested window would give a wrong completeness denominator even if every returned row looked valid. |
| The frozen manifest describes the intended source files. | It records the CDC address, selection, capture time, and byte fingerprints. | File length, digests, metadata identity, and supported fields are checked before use. | If both manifest and files were replaced consistently, checks could pass without establishing authenticity. External provenance remains unverified. |
| `mmwrweek_end` is a source-assigned surveillance reference week. | CDC's NREVSS overview describes collection-week reporting. The actual CSV gives an aggregate week-ending field, not individual sample dates. | The adapter checks its midnight-valued date format and Saturday endpoint. | Interpreting it as a precise test date would invent temporal detail and distort delay calculations. No individual-level timing is inferred. |
| `posted` is dataset publication metadata for a chronology check. | The live CDC metadata checked on 21 October 2026 defines it as the dataset publication date; the older bundled metadata capture omits the description. | A parseable value must not precede its reference week or follow capture; malformed values are flagged. The [source check](review-2026-10-21.md) records the definition. | Publication timing does not identify specimen collection, testing, or individual laboratory submission. No person-level delay is calculated from this field. |
| `detections` and `tests` belong to the same viral category and week. | This matches the CDC dataset's paired fields and test-positivity purpose. Aggregation uses their ratio, not patient counts. | Nonnegative integer counts, detections no greater than tests, and agreement with displayed percent positivity are checked. | Internally consistent but mismatched test pools could still produce misleading ratios. Laboratory-level membership cannot be verified from the extract. |
| Reported percentages are rounded to two decimal places. | The frozen displayed percentages have this precision. Half a 0.01-point unit gives a 0.005-percentage-point boundary. | Count ratios must agree within 0.005000000001 points, including a small numerical margin. | A source change in rounding or denominator definition would need review; the check does not validate an assay. |
| Missing, suppressed, invalid, and observed zero are different states. | Source notation distinguishes `*` and `.`; zero is a number, not a substitute for absence. | Separate states, zero-denominator behavior, and excluded records are tested. | Treating absence as zero would change both positivity and coverage. A suppressed underlying value remains unknown. |
| Unusable records stay out of pooled summaries. | This avoids calculating with ambiguous keys or invalid counts. It is a transparent rule, not a claim that exclusion is unbiased. | Quarantine and count reconciliation are tested; the basic audit excludes every duplicate copy. | If unusable records differ systematically, the usable subset can be biased. Coverage and findings must accompany the summary. |
| Each category has its own tested pool. | The aggregate data do not establish that categories refer to the same people or tests. | Calculations retain separate numerators and denominators. | Combining categories could double count observations or imply an unsupported comparison between populations. |
| The 0/7/14/28-day exclusions illustrate window sensitivity only. | They are preselected comparison settings, not fitted or evidence-based delay corrections. | Every calculation uses the same frozen release and an explicit cutoff. | An apparent robust trend could still reflect reporting revisions; an earlier information state is not reconstructed. |
| The 50% absolute denominator-change boundary is useful as an example flag. | It makes the diagnostic easy to inspect. No study cited here establishes a universal cutoff. | Strict comparison, consecutive calendar weeks, undefined ratios, and unchanged inclusion are tested. | Different choices change flags. Neither a flag nor its absence identifies the cause or validates stable reporting. |
| Synthetic expected calendars and dates are authoritative for their demonstrations. | Invented fixtures define known cases; they do not estimate real participation or delays. The basic audit ends weeks on Sunday; the vintage example ends them on Saturday. | Calendar keys and weekday conventions are checked separately. | Mixing these conventions would shift delay or due-date calculations. Their conclusions do not generalize to actual reporting performance. |
| Synthetic vintage rows are full replacements available on `issued_on`. | This is the explicit fixture contract. It illustrates the observation-time/availability distinction discussed by [Mellor et al. (2026)](https://pubmed.ncbi.nlm.nih.gov/42832413/), not a recovered CDC history. | Future versions are excluded; same-date conflicts fail; the newest invalid report is retained as invalid. | If real rows were incremental updates or arrival times were incomplete, the selection logic would be wrong. Those conditions are untested here. |
| Seven days is an illustrative lateness or grace setting. | It creates a transparent demonstration. No reference supplies an appropriate universal deadline. | Boundary behavior is tested; users can change the setting. | Counts of late, due, or missing reports depend on this choice. They are not measurements of CDC timeliness. |
| Two future captures with the same selection can be compared as saved states. | Separate capture times permit a bounded comparison of observed changes. Delphi documentation illustrates why snapshot and archive concepts differ. | The comparator checks input contracts, equal selections, and ordered capture times. | It misses intervening changes and cannot determine the first availability of a value. Only one real capture is bundled. |

All tests above are local software checks. The assumptions about real reporting processes, patient duplication, representativeness, operational utility, and clinical performance have not been independently validated. No method in this project estimates the unobserved infections or corrects selection into testing.
